## 三、作品集大类

**文件：`source/_data/portfolio.yml`**

顺序就是首页展示顺序，`name` 必须和文章里的 `categories` 一字不差。

```yaml
- name: 主图设计
  desc: 首屏五张图，决定点击率的那五张
- name: 详情页设计
  desc: 从卖点结构到视觉落地
- name: 店铺视觉
  desc: 首页、分类页、活动页的整体调性
- name: 活动KV
  desc: 大促主视觉与多尺寸延展
- name: 品牌与包装
  desc: 从线上视觉到实物物料
```

**`desc` 的写法**：一句话说清这一类解决什么问题，不要写「各类主图设计作品展示」这种废话。

**这五个大类出现在哪：**

1. 首页只放一个「作品集」大入口，下面是五个类目各取一张封面拼成的一排缩览图（点哪张都进 `/work/`）
2. `/work/` 页顶部是五个 tag 按钮，按钮上的数字是该类目下的项目数
3. 点 tag 直接进类目页 `/categories/<英文 slug>/`，这一页就是最里层的内容页，不再多一层
4. 类目页每条作品显示：标签、标题、正文前 78 字的摘要、日期、「查看项目 →」，右边是封面大图

所以 `desc` 现在只影响 `portfolio.yml` 的数据，页面上不直接显示；真正显示的是标题和摘要。想改摘要长度就改作品正文第一段。

## 四、单个作品

**位置：`source/_posts/`，一个作品一个 `.md` 文件，文件名用英文**

```markdown
---
title: 护肤品牌主图 · 极简白底
date: 2025-08-12 10:00:00
categories:
  - 主图设计
featured_image: /images/work/main-01.svg
tags:
  - 主图
  - 美妆
---

## 背景

两句话。什么品牌、什么品类、什么阶段。

## 要解决的问题

- 三条，写真实存在的难点，不要写「需要提升品牌形象」这种空话
- 每条一句话

## 我的做法

- 三条，写判断，不写流程
- 错误示范：先找参考，然后排版，最后调色
- 正确示范：背景压到比纯白低一档，让瓶身轮廓浮出来

## 结果

有数据写数据（点击率、转化、停留时长），没有数据写反馈。
```

**`featured_image` 的规格：**

- 比例 4:5，建议 1200×1500
- 格式 WebP 或 JPG，单张控制在 300KB 以内
- 放在 `source/images/work/` 下
- 这张图会同时出现在首页缩览图和类目页，所以要经得起缩小看

## 五、文章

**位置：`source/_posts/`，`categories` 写「文章」**

```markdown
---
title: 详情页第一屏，大部分人做错了什么
date: 2025-11-02 10:00:00
categories:
  - 文章
tags:
  - 详情页
  - 复盘
---
```

文章不需要 `featured_image`，首页文章列表只显示日期和标题。

**三个方向，好写也好读：**

1. 设计复盘 —— 一个项目做对了什么、错了什么
2. 工具与效率 —— 工作流、批量处理、字体、插件
3. 行业观察 —— 类目趋势、平台规则变化
